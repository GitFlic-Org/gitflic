# GitFlic — Git-хостинг и DevSecOps-платформа для разработчиков. Альтернатива GitLab и GitHub.
### GitFlic — Git hosting and DevSecOps platform for developers. An alternative to GitLab and GitHub.

**GitFlic — DevSecOps-платформа для разработки, хранения, проверки, сборки и безопасной доставки программного кода**. Она объединяет Git-репозитории, управление исходным кодом, code review, merge requests, issue tracking, CI/CD, документацию, реестры пакетов и контейнеров, инструменты безопасности, аудит и централизованное управление процессами разработки.

**GitFlic помогает командам выстраивать контролируемый процесс поставки приложений**: настраивать правила merge requests, обязательные проверки перед слиянием, политики доступа, ревью кода, пайплайны сборки и деплоя, аудит действий пользователей, управление артефактами и контроль жизненного цикла программных компонентов.

**Платформа** может использоваться как **альтернатива GitLab и GitHub** для работы с исходным кодом, CI/CD и командной разработки, а также как **замена Nexus, Artifactory и Harbor** для хранения и управления пакетами, контейнерными образами и build-артефактами.

**GitFlic is a DevSecOps platform for developing, storing, reviewing, building, and securely delivering software**. It combines Git repositories, source code management, code review, merge requests, issue tracking, CI/CD, documentation, package and container registries, security tools, audit capabilities, and centralized development governance.

**GitFlic helps teams build a controlled software delivery process** with configurable merge request rules, required checks before merging, access policies, code review workflows, build and deployment pipelines, user activity audit, artifact management, and software component lifecycle control.

**The platform** can be used as **an alternative to GitLab and GitHub** for source code management, CI/CD, and collaborative development, as well as a **replacement for Nexus, Artifactory, and Harbor** for storing and managing packages, container images, and build artifacts.

## Основные возможности

- **Git-хостинг и управление исходным кодом**: публичные и приватные репозитории, ветки, теги, права доступа и совместная работа над кодом
- **Code review и merge requests**: обсуждение изменений, ревью кода, обязательные проверки, правила слияния и контроль качества перед merge
- **Управление задачами и проектами**: issue tracking, доски задач, планирование работ и прозрачность процесса разработки
- **CI/CD и deployment pipelines**: автоматизация сборки, тестирования, доставки и развёртывания приложений
- **Реестры пакетов, контейнеров и артефактов**: хранение и управление пакетами, container images и build-артефактами как замена Nexus, JFrog Artifactory и Harbor
- **Безопасность разработки и DevSecOps**: интеграция проверок безопасности в процесс разработки, контроль зависимостей, политик и поставки кода
- **Аудит и управляемость**: журналирование действий пользователей, контроль доступа, централизованные политики и прозрачность изменений
- **Документация и база знаний**: ведение технической документации рядом с кодом, проектами и процессами разработки
- **Enterprise-ready сценарии**: централизованное управление командами, репозиториями, доступами, артефактами и процессами разработки
- **Инструменты для open-source и коммерческой разработки**: поддержка публичных проектов, закрытых корпоративных репозиториев и командной разработки

- **Tools for open-source and commercial development**: support for public projects, private enterprise repositories, and team-based software development

## GitFlic как альтернатива Sonatype Nexus и JFrog Artifactory

**GitFlic предоставляет встроенный реестр пакетов и артефактов**, который может использоваться как **альтернатива Sonatype Nexus и JFrog Artifactory**. Платформа позволяет хранить, публиковать и управлять пакетами, build-артефактами и зависимостями в едином контуре вместе с исходным кодом, CI/CD-пайплайнами, merge requests, аудитом и политиками доступа.

**GitFlic помогает** командам **централизовать управление артефактами** разработки: связывать пакеты и сборки с репозиториями, автоматизировать публикацию через CI/CD, контролировать доступ к артефактам, управлять жизненным циклом компонентов и выстраивать прозрачный процесс поставки программного обеспечения.

### GitFlic as an alternative to Sonatype Nexus and JFrog Artifactory

**GitFlic provides a built-in package and artifact registry that can be used as an alternative to Sonatype Nexus and JFrog Artifactory**. The platform allows teams to store, publish, and manage packages, build artifacts, and dependencies within a unified environment together with source code, CI/CD pipelines, merge requests, audit, and access policies.

**GitFlic helps teams centralize artifact management**: connect packages and builds with repositories, automate publishing through CI/CD, control access to artifacts, manage the software component lifecycle, and build a transparent software delivery process.

## GitFlic как альтернатива Harbor

**GitFlic предоставляет встроенный реестр контейнеров** для хранения и управления container images, который может использоваться как альтернатива Harbor. Команды могут публиковать, хранить и использовать контейнерные образы в единой DevSecOps-платформе вместе с Git-репозиториями, CI/CD, deployment pipelines, аудитом, политиками доступа и процессами разработки.

**GitFlic помогает упростить работу с контейнерными образами**: хранить images рядом с исходным кодом и пайплайнами, автоматизировать публикацию образов после сборки, управлять доступом к container registry, отслеживать действия пользователей и использовать контейнерные артефакты в процессах доставки и развёртывания приложений.

### GitFlic as a Harbor alternative

**GitFlic provides a built-in container registry** for storing and managing container images, which can be used as an alternative to Harbor. Teams can publish, store, and consume container images within a unified DevSecOps platform together with Git repositories, CI/CD, deployment pipelines, audit, access policies, and development workflows.

**GitFlic helps simplify container image management**: store images close to source code and pipelines, automate image publishing after builds, manage access to the container registry, track user activity, and use container artifacts across software delivery and deployment workflows.
